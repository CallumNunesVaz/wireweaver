## DeepSeek notes — build/test toolchain upgrade

### What changed (by file)

- `package.json` (devDependencies only — runtime `dependencies` untouched)
  - `@vitejs/plugin-react` `^4.3.1` → `^5.2.0`
  - `electron-vite` `^2.3.0` → `^6.0.0`
  - `vite` `^5.3.3` → `^8.3.8`
  - `vite-node` `^2.1.9` → `^6.0.0`
  - `vitest` `^2.0.0` → `^4.1.12`
- `package-lock.json` regenerated by the installs above.
- `electron.vite.config.ts`
  - Replaced the deprecated `externalizeDepsPlugin()` with `build.externalizeDeps: true`
    (electron-vite 6 still adds the externalize plugin automatically; kept explicit).
  - `build.rollupOptions` → `build.rolldownOptions` everywhere. This is required: Vite 8
    bundles with rolldown, and electron-vite 6's config preset reads
    `build.rolldownOptions.input` (not `rollupOptions.input`) when deciding whether an
    explicit entry is present. Leaving `rollupOptions` would make the main/preload
    entry detection fall back to `src/{main,preload}/index.ts` (which don't exist here)
    and throw "An entry point is required…".
  - Renderer `output.manualChunks` → `output.codeSplitting.groups`. Rolldown still
    accepts the function form of `manualChunks` (deprecated, Rollup-compat shim) but the
    idiomatic equivalent is `codeSplitting.groups`. Ported the five vendor splits using
    `test` regexes with `[\\/]` separators.
  - Gave the `react` group `priority: 10`. Rolldown's groups default
    `includeDependenciesRecursively: true`, so without a higher priority the `xyflow`
    group would hoist `react`/`react-dom`/`scheduler` (dependencies of `@xyflow/react`)
    into the xyflow chunk — which I observed on the first build (react chunk was 0.37 kB
    and react-dom ended up inside xyflow). Priority fixes that.
- `vitest.config.ts` → `vitest.config.mts`
  - Content unchanged (`environment: 'node'`, `include: ['tests/**/*.test.ts']` are both
    still valid in Vitest 4). Renamed to `.mts` so Vite 8 stops warning about "ESM
    syntax in a file loaded as CommonJS" under its future-native config loader
    (package.json has no `"type": "module"`; renaming is less invasive than setting it).
- `eslint.config.mjs`
  - Node-globals block now also matches `*.config.mts` (`*.config.{js,ts,mts}`).
- `.github/workflows/ci.yml` — no change needed. `node-version: 20` resolves to the
  latest Node 20.x (≥ 20.19), which satisfies Vite 8's `^20.19.0` engine requirement.
- `tests/smoke.test.ts` — no change. Verified `describe.skipIf(cond)('name', { timeout }, fn)`
  is still valid in Vitest 4 (`SuiteCollectorCallable` overload `(name, options, fn)`
  with `SuiteOptions extends TestOptions` providing `timeout`). It is collected and
  skipped cleanly under `npm test`.

### Design decisions & why

- **`rolldownOptions` over `rollupOptions`**: electron-vite 6 reads `rolldownOptions.input`
  directly in its preset/validator plugins; the `rollupOptions` alias is only set *after*
  the preset runs, so writing `rollupOptions` would silently break entry detection for
  the non-standard `electron/…` paths used by this repo.
- **`codeSplitting.groups` over `manualChunks`**: the correct rolldown-idiomatic
  replacement. The `react` priority bump is the one non-obvious piece (see above).
- **`@vitejs/plugin-react@5.2.0` instead of `6.x`**: both support Vite 8. v5 is the
  Babel-based line (peer `vite ^4.2 || ^5 || ^6 || ^7 || ^8`) and is the lower-risk choice
  for an unchanged React 18 app; v6 switches to the oxc/rolldown transform and adds
  optional peer deps. I picked the stable line.
- **`vite-node@6.0.0`**: the standalone `vite-node` package's current major depends on
  `vite ^8.0.0`, matching the rest of the toolchain, so `npm run mcp` keeps working
  unchanged (Vitest 4 no longer pulls `vite-node` in as a dependency).

### Guesses / uncertain

- The exact rolldown code-splitting semantics (group priority vs
  `includeDependenciesRecursively`) were inferred from the bundled type docs and
  confirmed empirically via build output, not from upstream prose docs.
- The `plugin-react` 5.x vs 6.x choice is a judgement call (both are "compatible" with
  Vite 8); 5.2.0 was chosen for stability. Flagging as uncertain whether the project
  would prefer the newer oxc-based 6.x.
